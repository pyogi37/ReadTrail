# Decisions

Append-only log. Each entry: date, decision, why, consequences. Product-level decisions also appear in `docs/PRODUCT-VISION.md`.

## 2026-09-13: Launch plan

1. **Launch target is a public Chrome Web Store listing.** Consequence: privacy policy URL, permission justifications, packaged zip, and store assets are required.
2. **1.0 ships everything except AI; 1.1 adds BYO-key AI.** Why: the first review should carry zero network or third-party data disclosure. Consequence: Phases 1 to 5 gate 1.0.
3. **Knowledge layer is a reader-facing, local-first feature.** Passages, notes, tags, search, connections, export/import. Passage text is stored only on an explicit save.
4. **AI is optional and uses the reader's own Anthropic key.** No hosted proxy, no accounts. Key stored in `storage.local`, never synced, with the plaintext risk stated in the UI.
5. **The Chrome Side Panel replaces the popup.** One entry point; `minimum_chrome_version` 114. Reading Space becomes the panel's library view, also openable in a tab.
6. **Session state is keyed per tab id, validated by URL.** Why: URL-keyed state produced cross-tab activation, orphaned reading locks, and lost updates. Consequence: `readtrail.tab.v1:<tabId>` records, `tabs.onRemoved` cleanup, sender-based trust rule.
7. **Content scripts stay statically injected on `*://*/*`.** Why: on-demand injection cannot serve side-panel activation or programmatic "Continue reading" tabs without per-origin prompts. Consequence: the store justification must document dormancy, backed by the dormancy test.
8. **Tab-close save offer uses a "recently closed" list plus badge, not `chrome.notifications`.** Why: least intrusive, no extra permission. Preference `closeSave` = ask, always, or never; default ask.
9. **Never add the `tabs` permission.** It adds a browsing-history warning; `activeTab` plus content-script host access covers every need.
10. **Claude Code leads, Codex reviews and drives browser QA, OpenCode free tier does bounded boilerplate.** `AGENTS.md` is canonical; `CLAUDE.md` imports it.
11. **License is MIT.**
12. **No new production dependencies, no bundler.** Playwright is a devDependency only for the e2e harness.

## 2026-09-13: Design tooling

13. **Side-panel polish uses the `impeccable` skill; motion stays CSS-only.** Why: impeccable runs in both Claude Code and Codex so both agents apply the same design rules; Framer Motion skills assume React, which ReadTrail does not use. Consequence: owner installs impeccable before Phase 3; every transition respects `prefers-reduced-motion`.

## 2026-09-13: Verified in Chromium (e2e harness)

14. **The worker never sees `tab.url` without the `tabs` permission.** Content-script host access does not expose tab URLs to `chrome.tabs.query` or `chrome.tabs.get`. Consequence: `getTabInfo` always falls back to the content script's `pageInfo` reply for http(s) tabs; this is the normal path, not an edge case. The `tabs` permission is still not added (decision 9).
15. **An extension page open in a tab carries `sender.tab`.** The panel's "Open in a tab" mode would have been keyed as a content script. Consequence: the trust rule checks the sender's extension origin before checking `sender.tab`, in the worker and in the library handlers (`isExtensionPageSender`).
16. **Playwright is the automated half of QA.** `npm run test:e2e` loads the unpacked extension in headless Chromium, serves fixtures over http, and drives the worker through a hidden extension page (a service worker cannot message itself). The real side panel surface stays on the manual checklist.

## 2026-09-13: Page-first library

17. **Pages are the primary library object.** Passages, notes, the saved reading position, and tags appear inside their page rather than as parallel top-level collections. Why: readers remember what they read as pages, while passages and notes are supporting material. Consequence: pages with any intentionally saved data appear in one unified Pages view.
18. **Tags belong to pages in 1.0.** Item-level tag fields remain accepted in the storage schema for export/import compatibility but are not exposed in the interface. A Tags view groups page tags and opens the matching pages. Item-level tagging can be reconsidered only with a distinct reader need.
19. **Search results are grouped by page.** Search still covers titles, URLs, passage text, note text, and page tags, but presents matching pages with their related contents together. Connections are deferred until their interaction model is designed; the initial Tags view supplies deliberate cross-page browsing without an unexplained recommendation layer.

## 2026-09-18: Product reset (2.0 direction)

Four concepts were generated independently and judged through three lenses (reader value, originality and coherence, feasibility and risk). `docs/PRODUCT-DIRECTION.md` holds the full recommendation.

20. **The draft is the cross-source object; the source stays the container.** A clip belongs to the page it came from and needs no filing decision. Thinking happens in a draft: an ordered list of the reader's text blocks and quote blocks. Why: the alternative, a named inquiry the reader switches between ("current trail"), is a mode, and a wrong mode silently misfiles a week of clips. Consequence: the page-first library of decisions 17 to 19 is kept intact and a `readtrail.draft.v1:<uuid>` record is added. No project, collection, trail, or thread record exists.
21. **Relations are quotations, not inferences.** Two sources are related because the reader quoted both in one draft. Consequence: `sidepanel/connections.js` (shared tag, same domain) is retired rather than surfaced, consistent with decision 19, and backlinks are derived at render time.
22. **Return never claims more than it knows.** Resolving both anchors is not enough to report "Found exactly": the resolved text, whitespace-normalised the same way capture normalises it, must equal the stored clip text. Why: the v2 structural check compares only a parent tag and a text length, so a rewritten paragraph of equal length would otherwise be flashed as an exact match. Consequence: three outcomes are always reported: exact, approximate ("the page has changed"), missing.
23. **Return reuses only a tab the reader already clipped from.** A session record `readtrail.seen.v1:<tabId>` is written when a clip is saved from a tab and removed when the tab closes. Why: the worker cannot see tab URLs (decision 14), and the alternative, asking every open tab where it is, would read tabs the reader never involved. Consequence: Return sometimes opens a second tab for a page that is already open. That is the acceptable cost.
24. **A tab opened by Return is told what to show through its own session record.** The tab record gains an optional `reveal` field, consumed once at bootstrap, exactly as Continue reading seeds a position. Why: a message would race the content script's injection at `document_idle`.
25. **The Desk is its own document.** The full-tab surface becomes `sidepanel/desk.html` rather than a mode of `sidepanel.html`. Why: serving a 280-pixel margin and a two-pane workspace from one file is two products in one file, and the panel's test harness would have to evaluate desk code. `sidepanel/` is already allow-listed, so packaging does not change.
26. **Return reads a source page only when the reader presses Return.** (Owner confirmed 2026-09-27.) Finding a saved clip resolves its anchors and, if they fail, searches the page for the clip's own words. This happens on that press and nowhere else, including on a dormant page. Nothing found during the search is captured, stored, or returned: the page replies with one of `exact`, `approximate`, or `missing`. Dormancy is otherwise unchanged, and no listener, canvas, pointer tracking, or reading-state write happens on a dormant page. Why this is a correction rather than a concession: "Save selection to ReadTrail" has never required activation either (`content/content.js`, the `capturePassage` branch, has no activation gate), so the absolute wording in `PRIVACY.md` was already inaccurate in 1.0. Consequence: the privacy documents state one rule, that nothing is read automatically and two actions read on request, and they disclose the `readtrail.seen.v1:<tabId>` session record. Proposal and reasoning: `docs/proposals/DECISION-26-WORDING.md`.

## 2026-09-27: Visual language

27. **One palette and one display face across both surfaces.** The panel and the Desk had drifted apart: the Desk had a serif display face and a warm ground, the panel had neither and read as a generic dark extension. Both now draw from one token set in `sidepanel/sidepanel.css`, which the Desk loads first. The ground is warm ink rather than blue-black, because ReadTrail is a reading instrument and should read as paper at night; the accent is the red of an annotation pencil; gold marks what the reader chose to keep. Georgia carries the display voice, and body copy stays in the system face, which is what a 280 pixel panel can actually set. Every foreground and background pair was measured: the lowest is 5.36 to 1 and most exceed 7 to 1.
28. **Motion is informational and never sits on a list item.** Every list rebuilds completely on each render, including on each keystroke in search, so an animation attached to a list item replays constantly. Animations are triggered by the interaction and die with the node: the block that moved, the card the reader opened, the message that appeared. A test fails if an animation is ever attached to a list item. The reduced-motion rule covers animation and scroll behaviour, not transitions alone as it did before.
29. **`impeccable` is an npm package, not a Claude plugin, and its detector is the usable half.** Correcting an earlier note in this session that said no such tool existed: it is `impeccable` on npm (Apache-2.0, no dependencies). `npx impeccable install` fails at the skill-bundle download with HTTP 404, so the skills are unavailable, but `npx impeccable detect <dir>` runs from the CLI itself and is worth using. It is never added to `package.json`; it is run on demand. Framer Motion stays rejected for the reason decision 13 gave: it is a React library and ReadTrail is plain JavaScript, so it would be a production dependency.
30. **The impeccable detector reports our whole dark palette as low contrast, and those findings are false.** It cannot resolve `color-scheme: dark` or our custom properties, so it measures our text against an invented light background (`#fdf4f4`), a colour that appears nowhere in this repository. On 2026-09-27 it reported 30 findings: 7 real (functional text below an 11px floor) and 1 real (white on the danger hover at 4.31 to 1), all fixed; the other 22 were this false positive. Do not restyle the palette to satisfy them. The real contrast figures are measured directly against `--surface` and recorded in decision 27.

## 2026-09-27: Critique of the Desk, two rounds

31. **Return names the tab it looked in.** Decision 22 said Return never claims more than it knows, and the worker held to that; the surface did not. The reply carries an `opened` flag and the Desk discarded it, so when Return opened a second tab the reader saw a confident verdict while the tab they were reading sat untouched. Every outcome now names where it looked.
32. **A verdict belongs to one press on one block.** Return's answer moved from a status line above the whole document into the quote it is about, told apart by rule colour as well as wording. The first attempt keyed the cache by passage id, which put an answer on a quote nobody had checked once the same clip was quoted twice: the product asserting a fact it was never told, which is worse than the problem it replaced. Each block now carries a key that travels with it, held outside the record so nothing extra is persisted.
33. **What Return found is kept.** A quote block carries an optional `checked: {quality, at}`. Optional, so older drafts still validate. A remembered outcome is worded differently from a live one and never repeats the clause about which tab was open, because that describes the moment rather than the quote. The draft can now say how many of its quotes still resolved.
34. **The solid accent is one control per surface; gold is Quote alone.** It had carried five meanings and stretched to fill its rows. Quote takes gold, which already means what the reader kept. Return and Continue reading share one quiet treatment, because both leave the surface; a first pass gave Continue reading the gold and drew the line on the wrong axis.
35. **One confirmation idiom, and it names the cost in numbers.** Four destructive actions had four protections, three of them native dialogs, and the most damaging had none: removing a clip severed every quote of it in every draft while nothing on screen changed. All of them now use the same inline row, and each counts what goes.
36. **A CSS animation shorthand never takes `var(--motion)`.** `--motion` carries its own easing for `transition`. Passing it to `animation` beside `var(--ease-out)` puts two easing functions in one shorthand, which is invalid, so the declaration is dropped and `animation-name` computes to `none`. Two of three animations had never run. A test that string-matches a stylesheet cannot prove an animation works; the guard is an end-to-end assertion on the computed value, verified to fail on the old shorthand.
37. **Provenance is the second-loudest thing in a quote block.** It had been set at the size and colour of "Insert text below", smaller than the quote it cites. Both critiques named this the clearest sign the composition was not authored for this product.
38. **The block plumbing recedes; the product's verbs do not.** A quote block carried six controls, four of them list plumbing, so the plumbing outnumbered the product two to one and a nine-block draft presented forty-four buttons. Return and Open page stay visible; move, insert and remove appear on hover or focus, and stay put where there is no hover.
39. **`impeccable` is an npm package whose skills install through `npx skills add pbakaus/impeccable`.** `npx impeccable install` fails at its own bundle download with HTTP 404. The skill and its files are git-ignored; `skills-lock.json` pins the version. Nothing is added to `package.json`, so the no-dependency rule holds. Its detector found real faults twice; its `low-contrast` rule is the false positive recorded in decision 30 and must not be acted on.

## 2026-09-27: Lessons from the third critique

40. **A trust-boundary signature covers only what the caller may not author.** The worker guards quote provenance by signing a stored block and matching it. Signing the whole block meant the Desk writing Return's own outcome looked like tampering, so every autosave after a Return was rejected and the reader silently lost what they typed next. The signature is passage id, text, url and title; `checked` is validated but not signed. Any future field a surface may legitimately write must be left out of it, and the check that a draft still saves belongs in the suite before the feature does.
41. **A page must not rebuild on its own writes.** `chrome.storage.onChanged` fires in the page that caused the change, so the live-update fix made the Desk reload after every autosave, taking the caret out of the block being typed in and destroying anything held in the block list. A reload now skips the editor when this page is mid-edit or when the record that came back is the one it just wrote.
42. **Transient interface state is rendered from state, never moved into a list that gets rebuilt.** The undo offer was moved into the block list and the next render wiped it, well inside the twelve seconds it promised.
43. **A confirmation focuses the way out.** The custom idiom that replaced three native dialogs focused the destructive button and ignored Escape, so one keypress destroyed a clip where the native dialog it replaced would have cancelled. Every confirmation now focuses Cancel and closes on Escape.
44. **Concealed controls are hidden from hit testing, not just from sight.** Hiding the block plumbing with opacity alone left a fully transparent "Remove block" as the topmost hit target at its own coordinates.
45. **A count is only reported for what was actually measured.** The draft summary counted checked quotes against every quote, so checking one of eight claimed something about seven the product never looked at, and it wore gold, the colour reserved for what the reader kept. It now names what it checked, breaks the outcomes down, and says how many it has not looked at.
46. **Three rounds, and each shipped a fix worse than the thing it replaced**: an animation that never ran, a verdict that appeared on a quote nobody checked, and a write that silently broke autosave. All three passed their tests. Every one of them was caught by measuring the running product rather than by reading the diff, and every replacement guard here asserts a computed or stored value, never the presence of source text.

## 2026-09-27: The fourth critique round

47. **Persisting an outcome means persisting its failures.** Decision 45 taught the summary to report only what it measured; the change that made that possible wrote `checked` on the success path alone. So deleting a clip left the last "found exactly" on the quote: the honest failure message lived for exactly one render, and every render after it, including after a reload, read the stale value back in gold. The summary never learned of the failure at all. A reveal that reports the clip gone now writes `checked` as `missing` with `reason: "clip-gone"`, saves, and re-counts. A reveal that merely could not open a page still writes nothing, because that says nothing about whether the quote holds — the distinction is the point, and the two must not collapse into one another.
48. **A quote that cannot be checked is not offered a check.** Leaving a Return on a quote whose clip is gone offers the reader a control guaranteed to fail identically forever. The row keeps Open page, which still works.
49. **The static detector cannot see the Desk, and three rounds of "0 findings" meant nothing.** Every list, block, quote and confirmation on the Desk is built by JS at runtime, so `impeccable detect sidepanel/desk.html` scans empty containers and reports clean. Scanning the *rendered* DOM, serialised out of the running browser with the real stylesheets beside it, finds `tiny-text` and `cramped-padding`. Any future detector run against a JS-built surface must scan the rendered DOM or be reported as uninformative.
50. **Return can only reuse a tab it was told about, and the panel's own Save selection never tells it.** The worker calls `rememberSeenTab` only when `isContentSender(sender)` holds, but `savePassageFromTab` sends `savePassage` from the side panel, an extension page with no `sender.tab`. Measured: three clips saved that way leave `readtrail.seen.v1` empty; one right-click clip writes a key at once. So the primary way to clip never teaches Return the tab, and because the record is session-scoped it is empty after every browser restart regardless. Known defect, not yet fixed; the wording stays honest about it, which is why it went unnoticed.
51. **A test fixture must not assert something untrue about the product.** The e2e Desk scenario seeded the seen-tab hint with a comment claiming that saving from the browser UI remembers the tab. It does not, and that sentence is the reason no test ever caught decision 50. The comment now states what is actually true.
52. **Four measured rounds, 19 → 21 → 19 → 20.** Three rounds of fixes moved the score one point, because each round's work went on repairing the honesty defect the previous round introduced. Flexibility has scored 1 in all four rounds and was never touched. The next piece of work is a deliberate pass at the quote block's controls — Return is 56px beside a 91px Remove — not another round of patches.

## 2026-09-27: Incognito, found during the manual QA

53. **A durable record about a page must be attributable to a tab.** The incognito refusal in `handleSavePassage` and `handleSaveNote` was guarded by `fromContent`, so it could only ever fire for a content script. The side panel's own Save selection sends `savePassage` from an extension page, where there is no `sender.tab`, so the product's primary way to clip was never checked at all: with ReadTrail allowed in incognito, a page read in a private window could leave a durable record of its text. Measured, not inferred — `isContentSender` is false for a real panel sender, and a save through that sender shape succeeded unconditionally. Now an extension page names a `tabId` and the worker resolves it, refusing an incognito tab, an unknown tab, and a missing or malformed id. `savePassage` and `saveNote` require it because they persist what was read from a page; `setPageTags` does not, because the library tags pages open in no tab, and a named tab is still refused.
54. **The guard reads only what the manifest allows.** `chrome.tabs.get` returns `incognito` without the `tabs` permission while leaving `url` and `title` undefined — verified in the running worker against the real manifest, whose permissions are `storage`, `activeTab`, `sidePanel`, `contextMenus`. So decision 14 holds: the worker still never depends on a tab URL it is not entitled to.
55. **A genuine incognito window could not be produced in the harness**, because the extension is not enabled in incognito by default and `chrome.windows.create({incognito: true})` returns no window. The refusal of an unknown, dead, or unnamed tab is proven in a real browser; the `incognito: true` branch is proven against a mocked tab table. Turning ReadTrail on in incognito and clipping was therefore left as a manual release check; the owner has since run it.
56. **Restart persistence verified for the first time.** Across a real profile restart: durable records survive and render, `chrome.storage.session` is completely empty, and no `readtrail.*` session key leaks. Previously only asserted in JSDOM.

57. **A control that is certain to be refused is not offered.** The published privacy policy says ReadTrail "never offers to save" an incognito page. The worker refused the record after decision 53, but the panel still showed Save selection, Add a note, the tag form and Save for later, so it offered and then failed — the policy overstated the product. The panel already received `incognito` from `getTabInfo` and dropped it on the floor; it now keeps it and withholds every control that would write a durable record, stating plainly that nothing is kept from an incognito window. This is the same rule as decision 48, applied to a different surface.
58. **The reading guide still runs in incognito.** Its state is session-only and dies with Chrome, which the policy already describes, so disabling it would remove a capability nothing requires. Only the durable offers are withheld.
59. **"Exclude this site" is withheld in incognito too**, although it is a setting rather than a save: it would durably record the host of a page read in a private window, which is the browsing history the policy promises not to keep.

## 2026-09-27: The independent Phase A review

The first review of the whole diff, by Codex, against `b49e2da`. Eight findings, four of them P1, plus confirmation of decision 50. All eight were verified here before anything was changed, and none was retracted. Every one lived in a path no test exercised: state that changes while a request is in flight, and import.

60. **A Return answer belongs to the quote that asked for it.** The callback held a numeric block index and resolved `current.blocks[index]` on the way back, so moving the quote before the answer arrived handed one quote's outcome to whichever quote had taken its place, and switching drafts wrote it into the new one. An index is a position, not an identity: the request now captures the draft id and the stable block key, re-resolves the quote on return, and drops the answer if it is no longer there. Decision 32 put the verdict on the quote; this makes it stay with it. The old guard resolved Return before moving the block, which is why it never saw the race.
61. **A failed save is kept per draft, and the reader is told which draft.** The failure marked `dirty` only while its draft was still open, so editing A, switching to B and watching A's save fail lost everything A held: reopening A reset `dirty` to false, showed the unsaved text, and never retried. The snapshot is now retained per draft, the index marks that draft "not saved", reopening it retries, and a failure about a draft that is not on screen names it instead of saying "Not saved" about nothing visible.
62. **Replace writes before it retires.** Import in replace mode cleared the library and then wrote. A failed write left the reader with nothing and an error naming storage. The new records go in first; only once they are stored are the old ones removed, so a failure anywhere leaves the existing library intact. Replacing with an empty export still empties the library, because that is what it says.
63. **Import cross-validates quote provenance.** `isValidDraft` says a quote is well formed, not that it is true. A payload could pair a real passage id with fabricated text, url or title, and Return would resolve the id and report the fabrication as found exactly — the one thing decision 40's signature exists to prevent, walked around through a file. Every imported quote is now checked against the passage it names, from the payload or already stored, and a draft with a contradiction is rejected. A quote whose clip is genuinely absent is legitimate and is kept with the reader's text, marked `clip-gone`, so nothing can later claim it resolved and no Return is offered on it.
64. **A reason is only coherent beside a missing outcome.** `{quality: "exact", reason: "clip-gone"}` validated and persisted, so one record could say the clip was gone while the summary counted the quote as held, in gold. Mine, from decision 53's own fix: a new field was validated in isolation and not against the field it qualifies.
65. **A content script never names the outcome.** The seeded path validated `quality`; the existing-tab path forwarded whatever it was handed, so a buggy response put an unknown quality on the quote as a `checked` record that every later save then failed to validate — a save failure with no explanation the reader could act on.
66. **A terminal reveal failure takes the seed with it.** The fifteen-second timeout cleared `pendingReveals` and left `reveal` in the tab record, so reloading that tab later still jumped and flashed at a passage Return had already said it could not reach. The seed is now removed on that path.
67. **The seeding race is not reachable at `document_idle`.** The reviewer also found that a content script could ask for the seed before the session write completed and never retry. The content scripts run at `document_idle`, so the page would have to load and go idle before one `storage.session.set` callback fires; it is reachable only by driving the worker's scheduler directly. Recorded rather than fixed. If it is ever seen in a real browser, the fix is the `tabs.onUpdated` push the launch plan already anticipates, not a retry loop.
68. **Decision 50 is fixed, and the test that hid it is gone.** The worker remembered a tab only for a content-script sender, so the panel's Save selection taught it nothing and every first Return opened a duplicate of the tab the reader was already reading. A guarded save from an extension page now asks that tab what it is showing, through its own content script, and remembers it only if it agrees — the caller's claim is never enough, and without the `tabs` permission a tab's URL cannot come from anywhere else. The end-to-end scenario used to write that record by hand; it now asserts the product wrote it.

## 2026-09-28: The quote block's controls

69. **A quote block leads with Return by consolidation, not by volume.** Return was 56px of 11px type beside a 91px "Remove quote", one of six equal chips, and the two product verbs were outnumbered by list plumbing in every block. Now a quote at rest offers three things: its source, its way back, and one control for everything else. The source title is the link to the page, which is what a citation is, so "Open page" stopped being a chip. Return is the one framed button left, 13px and 32px tall, outlined in the gold of the quote's own rule because it is that quote's way back. This refines decision 33 rather than reversing it: Return still is not a solid slab, and the solid accent is still one control per surface. It wins because nothing competes with it.
70. **The list plumbing lives behind one options control per block.** Move up, Move down, Add text below and Remove open from a quiet ⋯ that is always present and always hit-testable, so it can be found without hovering, which the old reveal-on-hover row could not. One block's options at a time. Remove ends the row, apart and in the colour that means it; it used to compute to exactly the colour, border and background of the control beside it. At phone widths and on touch the row becomes a tidy two-by-two. Tab stops in a quote block went from six to three.
71. **Shortcuts are taught where they are used, and work from anywhere in a block.** Each action shows its keys beside it and exposes them through `aria-keyshortcuts`; they lived only inside a help panel that was closed on load. Alt with an arrow and Control or Command with Enter now work from Return, the options control and the row, not only from a textarea. A key belongs to whoever handles it, and the owner stops it: the textarea's handler rebuilds the list, so letting its keys bubble on to the block moved or inserted twice. On a link, Control or Command with Enter is left to the browser, which opens it in a background tab.
72. **Keyboard moves keep the reader's place.** Moving a quote from the keyboard asked the rebuilt block for a textarea it does not have, found nothing, and dropped focus to the page. This was not found by any critique; it turned up while designing the options row. Focus now returns to the control that made the move, to its inverse at an edge, and otherwise to the block's writing area or Return, never to the citation link, whose Enter opens a tab.
73. **The undo offer belongs to the draft it was made in.** The offer is rendered from state on every rebuild (decision 42), and nothing cleared that state when the reader opened another draft, so for twelve seconds draft B showed draft A's "Undo remove", and pressing it spliced A's quote into B and autosaved it there. Latent since decision 42; caught by the pre-commit code review of this change, not by any test. Opening or closing a draft now withdraws the offer.
74. **A disclosure animates when it is opened, never when a render recreates it.** The options row carried its animation on the base class, so a row rebuilt already open by a move dropped in again on every press. The class is set by the toggle handler, the same rule `.page-body.just-opened` already followed.
75. **The undo offer is a list item, and that is deliberate.** A bare button in the block list was invalid structure (a list child that is not an item). As a list item it makes the list announce one more item than there are blocks for the twelve seconds it stands. The review flagged that; it is left as is, because the only alternative that keeps the count exact reintroduces the invalid structure, and the item announces itself as "Undo remove".

## 2026-10-09: What each clear covers

76. **Two clears, scoped by kind, and neither touches drafts.** The vision promised a way to "clear all records", and no reachable control does that today. The only button called Clear all sits in hidden markup and removes saved pages only; the visible **Clear saved places** and **Clear page content** each leave drafts, draft tags, and settings. The owner chose to describe what each clear covers rather than add a clear that removes drafts. Consequence: the vision, privacy policy, store listing, README, and manual QA all name the two clears; a draft is removed one at a time on the Desk.
77. **The hidden library section and `library-view.js` go now, not in Phase B.** The owner asked for it once the privacy policy was corrected. The section had been hidden since Phase 4, yet `library-view.js` shipped in the package, and 22 tests exercised a list and a Clear all that no reader could reach. Removed with them: `knowledgeView.countsFor`, which only the old list called, and eight CSS selectors that only matched that markup. One test was added in their place: a change to a saved place still reloads the library, a path the retired shell test had been the only one to cover. The worker's `removePageData` message is kept: no surface sends it now, but it is part of the validated protocol and has its own worker tests, so retiring it is a separate decision.

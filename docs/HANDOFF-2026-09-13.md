## Open review findings (from the final code review, most severe first)

Fix 1 to 5 before store submission; 6 to 10 can be 1.0.1.

1. **Recently closed list race.** `background/service-worker.js` `handleTabRemoved` (about line 660 to 700) does readRecent then writeRecent with no serialization. Closing a window with several active tabs drops entries. Fix: queue the onRemoved work through a single promise chain in the worker (a module-level `let queue = Promise.resolve()` that each handler appends to), or write per-tab keys `readtrail.recent.v1:<tabId>` and list by prefix.
2. **`tabs.onReplaced` bypasses save-on-close.** `background/service-worker.js` line 797 calls `removeTabRecord` directly. Fix: call `handleTabRemoved(removedTabId)` instead.
3. **Passage anchors are unbounded.** `background/library.js` `handleSavePassage` (about line 193) validates `start`/`end` with `S.isValidAnchor`. Fix: add `isValidSavedAnchor` in `shared/validators.js` that applies `isBoundedPath` and the offset limit, use it for passages and in `isValidPassage`.
4. **Page tags have no UI.** Nothing sends `setPageTags`. Fix: in `sidepanel/knowledge-view.js` (or page-view) add a "Tags for this page" input that sends `{type:"setPageTags", url, tags}`; or drop page tags from ARCHITECTURE.md and PRIVACY.md for 1.0.
5. **No bulk clear for passages and notes.** Nothing sends `clearLibrary`; PRIVACY.md promises it. Fix: add a "Clear passages and notes" button with confirmation in the knowledge section that sends `{type:"clearLibrary", kinds:["passages","notes","pagemeta"]}`.
6. **`handleSetSettings` lost update** (`service-worker.js` about line 165). Same serialization fix as item 1, or make `excludedHosts` edits go through dedicated add/remove messages.
7. **Inline error strings.** `content/passage.js` line 38 returns `"too-long"` (not in `ERRORS`); `content/content.js` and `sidepanel/page-view.js` compare `"no-selection"`, `"inactive"`, `"superseded"` as literals while `ERRORS.NO_SELECTION` etc. are unused. Fix: add `TOO_LONG` to `shared/constants.js` and reference `SHARED.ERRORS.*` at each site.
8. **`countEntries` reads all of storage per save** (`background/library.js` line 118). Fix: keep a counter in `readtrail.library.v1` updated on write/remove/clear/import, recount only when the key is missing.
9. **`RESTORE_QUALITIES` defined twice** (`shared/validators.js` 154, `shared/page-controls.js` 7) plus literals in `content/position.js`. Fix: define once in `shared/constants.js`.
10. **Dead `extensionOrigin()`** in `service-worker.js` line 41; sender-trust helpers live in `background/library.js`. Fix: delete it; move `isExtensionPageSender`/`isContentSender` to a small `background/senders.js` or into the worker.

Lower-priority cleanup noted but not ranked: five copies of a `sendMessage` wrapper across `sidepanel/*.js`; four copies of `domainFromUrl`; `snapshotPosition` in `content/content.js` duplicates `clonePosition`; `handleSavePassage`/`handleSaveNote` are near copies; `library.keys` is collected but unused; `renderSearch` does O(n) finds per result; `refreshHighlights` fires in every active tab on any passage change; the `source:"ai"` note field is 1.1 schema shipped early (harmless, but AGENTS.md says stay in sprint).

## Two facts verified in Chromium (already recorded in DECISIONS 14 and 15)

- The worker never sees `tab.url` without the `tabs` permission. `getTabInfo` falls back to the content script's `pageInfo`; that is the normal path.
- An extension page open in a tab carries `sender.tab`. The trust rule checks the extension origin first (`isExtensionPageSender`). Keep that order.
